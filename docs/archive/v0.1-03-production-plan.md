# 03｜整體計畫與執行步驟（v0.1）

> 本計畫以 Q1–Q3 的**預設假設**為前提：PC/Steam、Godot 4、1–4 人合作、約 16 個月進 Early Access。收到回覆後，第 2 節的時程和第 4 節的人力會相應調整。

---

## 1. 開發策略

1. **先驗證最大的未知：異能發現好不好玩。** 寫任何程式之前，先用紙上原型測試推理板。
2. **垂直切片是關卡。** 切片沒有通過玩家測試指標，就不擴充內容。
3. **先建事件紀錄器。** 群心演化、結案報告、平衡分析都依賴它，所以它是第一個要做的系統。
4. **內容全部資料化。** 異能、兵種、事件、NPC、共鳴物都用資料檔定義。企劃可以自己加內容，不必等工程師。
5. **每兩週出一個可玩版本。** 每個月有一場內部 Playtest，每季有一場外部 Playtest。

## 3. 執行步驟（前 12 週詳細，之後依里程碑展開）

### 第 1–2 週：決策與啟動

1. **回覆 Q1–Q3**，鎖定平台、人數、分級和授權策略。
2. **授權與顧問：** 發出和中央警察大學洽談的意向（公共事務或秘書室窗口），同時決定替代校名。招募 1–2 名在校生或校友擔任校園生活顧問。
3. **建立專案基礎設施：**
   - Git 加 Git LFS 管理美術素材
   - 分支策略
   - CI 每日自動建置（Windows 和 Linux）
   - 任務看板
   - 文件站（就是這個 `docs/`）
4. **確立設計支柱並全員共識**，產出一頁式設計支柱海報。

### 第 2–4 週：紙上原型與技術驗證

5. **推理板紙上原型：** 做成卡牌桌遊。一人扮演「世界」，手上有隱藏的異能卡；玩家透過「行動卡」觀察徵兆、推理。測試 8 個原型、10 名以上受測者。
6. **技術驗證 A，連線：** Godot 4 + GodotSteam，4 人同步移動和射擊，測量延遲容忍度。
7. **技術驗證 B，蟲群：** Flow Field 尋路，300 隻蟲同時在畫面上，維持 60fps，並驗證主機到客戶端的同步頻寬。
8. **技術驗證 C，光影與霧：** 2D 光源、手電筒光錐、林口霧 Shader、色盤侵蝕效果。

### 第 3–6 週：美術與地圖

9. **畫三張關鍵場景圖：** 第 0 幕「早點名的升旗場」、第 2 幕「停電的宿舍走廊」、第 4 幕「蝕潮中的射擊館」。
10. **定下 Sprite 規格：** 角色 16×32，八方向；蟲族剪影表；UI 卷宗風格稿。
11. **做校區灰盒地圖：** 依研究文件的建築清單做虛構化配置，先決定動線和各區塊的玩法定位。

### 第 5–12 週：垂直切片核心系統（依相依性排序）

12. **角色控制與戰鬥：** 移動、閃避、近戰、射擊、體力。
13. **事件紀錄器：** 所有可記錄的行為都寫成結構化事件。
14. **異能框架：** 語法資料格式、徵兆觸發、覺醒日誌、推理板 UI、實驗判定、命名。
15. **蟲族 AI：** 嗅蟲、工蟲、刃螳、擬物蟲；費洛蒙系統；感知五管道。
16. **導演 AI v1：** 緊張度模型和生成預算。
17. **NPC v1：** 15 名 NPC；救援、跟隨、基本對話；記憶標籤。
18. **Storylet 引擎和 30 個事件。**
19. **末日晚點名：** 存檔、當日結算、群心演化回合 v0。
20. **結案報告 v1：** 模板產生器和分享卡輸出。
21. **兩輪內部 Playtest、一輪外部 Playtest**，依遙測和訪談修正。

### 第 13 週以後

22. 依第 2 節進入 P2 Alpha，按「系統優先 → 內容擴充 → 平衡」的順序推進。

## 5. 品質指標（遙測）

| 指標 | 目標 |
|---|---|
| 首局玩家發現第一個要素的時間 | ≤ 15 分鐘 |
| 平均異能探索度 | 50–70%（太高代表太簡單） |
| 首局通關率（存活到第 7 天） | 15–25% |
| 「再一局」率（結算後 5 分鐘內開新局） | ≥ 50% |
| 每日種子參與率 | ≥ 20%（EA 之後） |
| 報告分享率 | ≥ 10% |
