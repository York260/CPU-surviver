# 03｜迭代計畫（v0.2）

## 1. 迭代原則

1. **每一輪結束都要有一個可以玩的版本。** 不做「做完一半、還不能玩」的輪次。
2. **每一輪只回答一個核心問題。** 例如「打起來有沒有手感？」，答案來自試玩，而不是猜測。
3. **由下往上蓋。** 依照模組依賴圖（02 第 1 節）的順序實作，地基沒穩不往上蓋。
4. **完成的定義要具體。** 達不到「完成定義」就不進下一輪。
5. **回饋決定下一輪的細節。** 計畫是骨架，每一輪的內容會依照上一輪的試玩回饋調整。

## 2. 每一輪的流程

```
① 我開發 → ② 自動測試全部通過 → ③ 交付「本輪說明」
   → ④ 你試玩（需要時約朋友） → ⑤ 你回饋 → ⑥ 我修正、調整下一輪
```

**本輪說明**的內容：
- 這一輪新增了什麼
- 怎麼啟動
- 這次要請你特別注意的地方（3–5 個問題）
- 已知問題

## 4. 各輪細節

### I0 地基
- **範圍：**
  - 專案骨架：TypeScript monorepo、測試、CI
  - M00 核心：世界、排程、Tick、亂數流、事件、序列化
  - 一張用程式產生的測試地圖
  - 一名玩家，可以用 WASD 移動
  - 除錯面板 v1：按 F1 開啟，可以看實體資訊、暫停、逐格執行
- **不做：** 網路、戰鬥、美術
- **為蛻者預留：** 通用元件 `Faction`、`Traits`、`Controller`、`Form`。玩家和蟲族都用同一套元件（見 specs/M05-molter.md 第 9.2 節）
- **完成定義：**
  - `npm test` 在 CI 上全部通過
  - 在瀏覽器裡可以移動
  - 同一個種子加上同一串輸入，會跑出完全相同的結果（重播測試通過）
- **你要做的：** 安裝 Node.js 和 Git，照我的步驟在你的電腦上跑起來，然後截一張圖給我。

### I1 一起走路
- **範圍：**
  - Node 伺服器、用 4 碼代碼建立和加入房間
  - 1–4 人連線、斷線重連
  - 伺服器權威模擬；客戶端插值，自己的移動有預測
  - 校區灰盒地圖 v0：我依照參考資料先畫第一版，你再修正
  - 為蛻者預留：快照分視角的掛鉤 `visibleTo`（先一律回傳 true）
  - 部署指南，提供兩種方案：
    - 方案 A：你的電腦開伺服器，再用穿透工具讓朋友連進來
    - 方案 B：免費的雲端方案
- **完成定義：** 你和一位朋友從不同的網路連線，一起走動 10 分鐘，畫面同步、手感可以接受。
- **你要做的：**
  - 照指南部署一次
  - 告訴我灰盒地圖哪裡和你記憶中的校園不一樣（手繪照片也可以）

### I2 第一隻蟲
- **範圍：**
  - 近戰和投擲、受擊回饋、擊退
  - 倒地、扶起、觀戰
  - 嗅蟲：徘徊、追擊、用費洛蒙呼叫同伴
  - 一個裂隙生成點、固定波次
  - 所有手感參數都放在資料檔裡
  - 淘汰處理寫成資料驅動的狀態機，MVP 只啟用倒地、死亡、歸隊；觀戰時可以在地圖上標記位置
- **效能驗證：** 同一個畫面 200 隻以上的蟲。
- **完成定義：** 2–4 人打 10 分鐘，至少經過兩輪調整，手感被評為「還不錯」。

### I3 活過三天
- **範圍：**
  - 日夜循環：一天約 10 分鐘
  - 導演 v2：用緊張度決定波次
  - 新兵種刃螳
  - 撿拾和物品欄（6 格）、飢餓、醫療包、路障
  - 點名檢查點：存檔、當日小結
  - 勝負判定：撐過三天就贏，全隊倒下就輸
  - 簡易結算畫面
- **完成定義：** 一局 30–40 分鐘可以從頭玩到尾，結束後有人想再開一局。

### I4 未知的自己（★ MVP）
- **範圍：**
  - 6 個異能原型。每一局、每位玩家隨機分配一個。
  - 代價引擎 v1
  - 發現 v1：徵兆、日誌、三欄推理板、實驗、命名
- **完成定義：** 在第一次遊玩中，半數以上的玩家為自己的異能命名，而且至少出現一次「原來是這樣！」的反應。

### I5–I8
大方向照路線圖。開始做這幾輪之前，我會依照 MVP 的試玩回饋重新規劃細節。
